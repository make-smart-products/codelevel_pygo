# Раздел 1. Разработка и работа серверов

Учебный проект канала CodeLevel. Раздел состоит из 19 материалов от устройства HTTP-запроса до сборки приложения и основ размещения. Нужны Git и актуальный стабильный Go. Синтаксис маршрутов требует Go 1.22 или новее. Все зависимости проекта входят в стандартную библиотеку.

Установи инструменты, затем скачай проект и запусти сервер.

```sh
go version
git clone https://github.com/make-smart-products/codelevel_pygo.git
cd codelevel_pygo/editorial/go_server
go run .
```

В другом терминале выполни команды. В PowerShell используй `curl.exe`.

```sh
curl -i http://127.0.0.1:8080/healthz
curl -i http://127.0.0.1:8080/api/hello/Ada
curl -i http://127.0.0.1:8080/api/hello/Ada123
curl -i -X POST http://127.0.0.1:8080/healthz
```

Первые два запроса вернут `200` и JSON. Третий даст `400`, четвёртый — `405` с допустимыми методами в заголовке `Allow`. Сервер слушает локальный адрес `127.0.0.1`. Нажми Ctrl+C, чтобы запустить штатное завершение.

Выполни `go test ./...`, чтобы проверить маршруты. Затем добавь `GET /api/version` и тест на его ответ.

## Сборка

Останови предыдущий процесс через Ctrl+C. В каталоге `editorial/go_server` выполни команды.

```sh
go test ./...
go build -o server .
./server
```

На Windows в PowerShell используй `go build -o server.exe .` и `.\server.exe`. Сборка создаёт файл, а последняя команда запускает его процесс. Для проверки открой второй терминал и запроси `/healthz`. Компилятор создаёт файл для выбранных ОС и архитектуры.

## Основы размещения

В примере приложение слушает `127.0.0.1:8080`. В схеме размещения обратный прокси работает на той же машине, принимает HTTPS на публичном порту 443 и передаёт запросы локальному приложению. DNS-имя указывает на публичный адрес машины. Сетевой экран разрешает нужные внешние подключения, прокси использует действительный TLS-сертификат, менеджер процессов обеспечивает запуск после перезагрузки и сбор журнала.

Такую схему нужно проверить по цепочке от домена и HTTPS до `/healthz`, журнала ошибок и штатного завершения процесса. [Пример устройства обратного прокси](https://caddyserver.com/docs/quick-starts/reverse-proxy)

## Разбор схем

Первая схема показывает путь запроса. Клиент открывает соединение и отправляет метод с адресом. `http.Server` читает HTTP-запрос и передаёт его настроенному `Handler`. В этом проекте обработчиком верхнего уровня служит `ServeMux`. Он выбирает функцию, которая сформирует ответ. Заголовки и тело уходят клиенту по соединению.

Вторая схема разбирает `GET /api/hello/Ada`. Метод `GET` подходит шаблону `GET /api/hello/{name}`, а сегмент `Ada` становится значением `name`. Функция `hello` читает его через `r.PathValue("name")`, проверяет символы и формирует JSON. Для неизвестного пути маршрутизатор отвечает `404`. Для зарегистрированного пути с неподдерживаемым методом он отвечает `405`. Шаблон `GET` также принимает `HEAD`.

Третья схема связывает настройки времени с этапами работы соединения. `ReadHeaderTimeout` ограничивает чтение заголовков. `ReadTimeout` охватывает чтение запроса вместе с телом. `WriteTimeout` ограничивает время записи ответа. `IdleTimeout` задаёт ожидание следующего запроса по keep-alive соединению. Значения в примере подходят для небольших JSON-ответов, при проектировании потоковых ответов бюджеты времени нужно выбрать отдельно.

При Ctrl+C контекст сигнала запускает `Shutdown`. Сервер перестаёт принимать новые соединения, закрывает простаивающие и ожидает завершения активных запросов. После истечения пяти секунд ожидание возвращает ошибку, а программа завершает процесс. `ListenAndServe` при штатном закрытии возвращает `http.ErrServerClosed`, который в примере обработан отдельно от ошибки запуска.

## Как следовать публикациям

В уроке 3 запусти полный проект. В уроке 4 повтори минимальный пример в отдельной папке. Перед уроком 8 останови минимальный сервер и вернись к полному проекту. Так будут доступны оба маршрута, проверка имени, таймауты и обработка Ctrl+C. В уроках 17–19 проверь тесты, сборку и схему размещения.

Серия содержит 13 иллюстрированных разборов и шесть викторин с объяснением ответа. Каждому материалу соответствует отдельная иллюстрация с Гофером. Для викторин картинки показывают ситуацию без выделения правильного варианта. Картинки и запросы к ImageGen находятся в папке `images`. Тексты и порядок раздела заданы в `server_section.py` в корне репозитория.

Перед отправкой публикация проверяет отпечаток изображения по истории очереди. При повторе отправка останавливается на этом материале до подготовки новой картинки. Состояние очереди сохраняет отпечатки успешно отправленных изображений вместе с прогрессом.

- [Справочник net/http](https://pkg.go.dev/net/http)
- [Маршрутизация в Go 1.22](https://go.dev/blog/routing-enhancements)
- [Справочник httptest](https://pkg.go.dev/net/http/httptest)

Персонажа Go Gopher придумала Рене Френч. Иллюстрации серии созданы в ImageGen по мотивам оригинала. [История и лицензия Go Gopher](https://go.dev/blog/gopher)
